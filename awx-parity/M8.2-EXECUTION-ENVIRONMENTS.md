# M8.2 — AWX execution environments

Status: **IN PROGRESS — model and validation committed; no runnable EE integration yet.**

M8.1 handoff: implementation delivered; manual validation explicitly deferred by user. Its verification backlog remains a release blocker. HA parked. Keycloak OIDC only; no SAML.

## Scope and completion criteria

1. OCI digest-pinned execution environment definitions, including image, pull policy, registry credential reference and project-level access.
2. Persist environment definitions and template selection with migrations and backup/restore.
3. Runner-side container runtime adapter (Podman or Docker) with per-job isolation, non-root identity, bounded CPU/memory/PIDs, timeout, restricted network policy, no privileged containers, read-only root filesystem when possible.
4. Secure mounting of inventory, repository, SSH/credential material and temporary working directory. Secrets never in process arguments, images, or persisted logs; cleanup on cancellation and failure.
5. Runtime capability discovery: Linux container workers only for this phase; Windows workers must reject unsupported EE execution clearly rather than silently running on host.
6. Queue/dispatch constraints: only runners advertising EE support can accept EE tasks; concurrency and offline recovery.
7. Capture logs, status, cancellation, exit codes and image digest for audit; prevent privilege escalation from user-controlled image names or runner tags.
8. API/UI for administrators to manage EEs and template users to select allowed environments.
9. Tests: validation, DB migrations, authorization, runtime invocation, cancellation, cleanup, missing image, registry failures, malicious inputs, Docker/Podman integration.
10. Documentation, rollout, upgrade and rollback.

## Delivered

- `db/ExecutionEnvironment.go`: typed EE definition and fail-closed SHA-256 digest/pull-policy validation.
- `db/ExecutionEnvironment_test.go`: unit cases for pinned images and invalid input.

## Explicitly not delivered yet

No persistence, API, UI, container execution, registry auth, dispatch capability negotiation or production integration. Go tests are not verified. This milestone is **not complete** and must not be represented as AWX EE parity.
