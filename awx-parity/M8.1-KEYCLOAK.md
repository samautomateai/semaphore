# M8.1 — Keycloak OIDC implementation checklist

Scope: OIDC + Keycloak only. **No native SAML implementation.** HA stays parked on `feature/postgres-ha`.

## Confirmed source behavior
- `api/login.go` supports configured OIDC providers, discovery, state-cookie CSRF matching, ID token verification, and external identity resolution.
- `syncLoginRoles` delegates to an injected `pro_interfaces.RoleSyncService`; inspect its Community implementation before claiming Keycloak group mapping is functional.
- `db/RoleMappingStore_pro.go` defines an interface only; it does not establish Community persistence.
- `db/Role.go` defines global/project role permissions, but actual Community enforcement and management must be traced.

## Security fixes
- `b1c6e7e`: OAuth state cookie expiry reduced from one year to ten minutes; explicit root path and HTTPS-aware Secure flag. **Committed, not tested.**
- Remaining: ensure callback consumes state once, bind state to provider, verify replay behavior and session revocation, and add automated tests.

## Keycloak acceptance criteria
1. Authorization-code login via Keycloak discovery and verified ID token, rejecting incorrect issuer/audience/nonce/state.
2. Stable `iss+sub` account mapping; never adopt a local administrator by email.
3. Keycloak groups grant least-privilege project roles, with explicit removal on group revocation.
4. Fail closed on unavailable/malformed group claims; prove Community role mapping persistence and authorization.
5. Break-glass local admin remains available and audited.
6. Login/logout, session expiry, permission denial and role changes have audit events.
7. Negative tests cover replay, cross-provider state, unverified email and privilege escalation.
